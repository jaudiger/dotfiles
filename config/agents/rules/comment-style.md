# Human-sounding code comments

MUST write concise, direct comments in a natural developer voice. Inside function bodies, keep comments to one short sentence or a few words. Keep doc comments concise and direct. MUST NOT restate what the code already says. Avoid formal phrasing, including "It should be noted that..." and "This function is responsible for...". Avoid hedging, including "This might be needed because...". State the fact or remove the comment.
